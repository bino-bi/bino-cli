`Text` manifests define text values that can be used directly or as children of layouts and cards.
They can optionally bind to one or more datasets and support font-size scaling to fit the available space.

## Minimal definition

This is the smallest well-formed `Text`: the required `value` plus the `dataset` the
commentary reads its numbers from.

```yaml
apiVersion: bino.bi/v1alpha1
kind: Text
metadata:
  name: reportSubtitle
spec:
  dataset: kpi_summary
  value: |
    **H1 2025 Summary**

    Total revenue reached **EUR ${data.kpi_summary[0].ac1}m**, exceeding plan by **+3.6%**.
```

A single dataset name is the common case; `dataset` also accepts an array of names or an
inline `DataSet` definition (see [Template expressions](#template-expressions) for how the
bound rows are addressed).
All attributes are listed in the [Attribute Reference](#attribute-reference) below.

Fields:

- `spec.value` - required string. Supports **Markdown** syntax (see below) and **template expressions** (see below).
- `spec.dataset` - optional dataset reference; a single name, an array of names, or an inline [`DataSet`](/reference/dataset/) definition.
- `spec.scale` - optional scaling mode (see [Scaling](#scaling)).
- `spec.selectedStyle` - optional name of a [`ComponentStyle`](/reference/component-style/) to apply; merged over the `_system` and `_default` styles.
- `spec.i18nNamespace` - optional [i18n namespace](/reference/internationalization/#scoped-overrides-with-i18nnamespace) for this component's labels; when unset it is inherited from the nearest ancestor that carries one.

## Markdown support

The `value` field accepts Markdown. The Markdown is converted to HTML at build time
and the resulting HTML is placed in the `bn-text` element's `value` attribute.

Plain strings still work - they are wrapped in a `<p>` tag automatically.

### Examples

**Bold and italic text:**

```yaml
spec:
  value: "**Revenue** grew by *12%* this quarter"
```

**Links:**

```yaml
spec:
  value: "Source: [World Bank](https://data.worldbank.org)"
```

**Lists:**

```yaml
spec:
  value: |
    Key findings:

    - Revenue up 12%
    - Costs down 3%
    - Net margin improved
```

**Asset images:**

You can embed images from [`Asset`](/reference/asset/) manifests using the `asset:` URL scheme:

```yaml
spec:
  value: "![Company Logo](asset:brandLogo)"
```

The `asset:` prefix is resolved at build time to the actual URL. See the [Asset reference](/reference/asset/#using-assets-in-markdown-images) for details.

**Mixed formatting:**

```yaml
spec:
  value: |
    ### Regional Summary

    | Region | Growth |
    |--------|--------|
    | EMEA   | +8%    |
    | APAC   | +15%   |

    > Data as of Q4 2025
```

## Template expressions

The `value` field can hold placeholders for dynamic content.
The engine replaces them in the browser with values from the bound datasets and with translations.
Nothing is evaluated: a placeholder is a lookup, not JavaScript.

These placeholders are replaced:

- `${data.<dataset>[<row>].<field>}` - one field of one row of a bound dataset. `<row>` is the row number, starting at 0.
- `${data['<name>'][<row>].<field>}` - the same for a dataset name that is not a plain identifier, such as `laptop-revenue`.
- `${t('<key>')}` - looks the key up in the component's i18n namespace (set via `i18nNamespace`, otherwise inherited from the nearest ancestor carrying one; keys missing there fall back to `_system`) for the artefact's language; an unknown key renders as the key itself. See the [Internationalization reference](/reference/internationalization/).
- `${t('<key>', { name: 'text', count: 3, value: data.kpi[0].ac1 })}` - a translation with parameters for its `{{name}}` placeholders. A parameter is a text in single quotes, a number or a dataset path.

Write the strings inside a placeholder in single quotes. Double quotes in Markdown text are escaped at build time, and such a placeholder is printed as written.

```yaml
spec:
  dataset: kpi_summary
  value: "Revenue: ${data.kpi_summary[0].ac1}"
```

```yaml
spec:
  value: "${t('report.title')}"
```

Any other `${...}` is printed as written. That includes arithmetic (`${data.kpi[0].ac1 / 1000}`), method calls (`${data.kpi[0].ac1.toFixed(1)}`) and conditions. Compute such values in the DataSet SQL and read the result with a placeholder.

Dataset values and translations are HTML-escaped, so they are shown as text.
A placeholder that does not resolve (unknown dataset, row or field) renders empty and sets a `WARN_value_path` warning on the component.

Write placeholders plain: only a bare name such as `${NAME}` or `${NAME:default}` is expanded as an [environment variable](/appendix/runtime-limits/#environment-variable-substitution).

### Security

No code from `value` is run. The HTML output is **sanitized** against XSS:

- Allowed elements: `br`, `b`, `i`, `strong`, `em`, `span`, `p`, `div`, `h1`-`h6`, `ul`, `ol`, `li`, `table`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`, `sub`, `sup`, `small`, `hr`, `a`, `img`, `code`, `pre`, `blockquote` and `del`.
  An element that is not allowed is removed together with its content.
- Allowed attributes: `class`, `style`, `href`, `src`, `alt`, `title`, `width`, `height`, `colspan` and `rowspan`.
  All others are removed, including event handlers (`onclick`, `onerror`, …).
- `style` is kept only when it is exactly `text-align: left`, `text-align: center` or `text-align: right`.
- `href` and `src` accept `http`, `https`, `mailto` and relative URLs. `src` also accepts `data:` URLs.
  Any other scheme, such as `javascript:`, removes the attribute.

## Scaling

The `scale` field controls how the text component scales its font size
to fit within the available parent space. Scaling considers **both width and height** -
the tighter constraint wins.

| `scale` value                | Behavior                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------- |
| _(not set)_                  | Auto-scale to fit; emits an `AUTO_scale` warning with the applied factor        |
| `"none"`                     | No scaling; emits `WARN_overflow` warning if content overflows                  |
| `"auto"`                     | Auto-scale to fit, silently (no warning)                                        |
| `"0.5"`, `"0.8"`, `"1.2"`, … | Apply `baseFontSize × factor`; emits `WARN_overflow` if content still overflows |

Other values (negative or zero factors, non-numeric strings, unrecognized keywords) are
rejected by schema validation, so they never reach the renderer.

```yaml
spec:
  value: "This text will shrink to fit its container"
  scale: auto
```

```yaml
spec:
  value: "Fixed 80% size"
  scale: "0.8"
```

## Standalone text manifest

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: Text
metadata:
  name: mainTitle
spec:
  value: "Sales Overview Report"
```

## Text as a layout child

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: LayoutPage
metadata:
  name: sales_layout
spec:
  pageLayout: full
  children:
    - kind: Text
      spec:
        value: "Sales Overview Report"
        scale: auto
```

| Attribute              | Type   | Required | Default | Description                                                                              |
| ---------------------- | ------ | -------- | ------- | ---------------------------------------------------------------------------------------- |
| `apiVersion`           | string | yes      | -       | Must be `bino.bi/v1alpha1`.                                                              |

| `metadata.description` | string | no       | -       | Free-form description.                                                                   |
| `metadata.constraints` | array  | no       | -       | Conditional inclusion rules. See [Constraints](/concepts/constraints-and-scoped-names/). |
