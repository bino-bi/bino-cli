title: Grid
description: Create tabular layouts with row and column headers for organizing child components.
---

`Grid` manifests define CSS grid-based layouts with row and column headers, allowing you to organize child components in a structured tabular format. Grids are useful for creating dashboards, comparison views, and data matrices where components need to be arranged in rows and columns.

## Minimal definition

This is the smallest well-formed `Grid`: the required headers and children plus
`chartTitle`, which every grid should set - without it the title area is omitted
and the matrix carries no message.

```yaml
apiVersion: bino.bi/v1alpha1
kind: Grid
metadata:
  name: product-comparison
spec:
  chartTitle: Product Performance Matrix
  rowHeaders:
    - label: Laptops
      id: laptops
    - label: Tablets
      id: tablets
  columnHeaders:
    - label: Revenue
      id: rev
    - label: Trend
      id: trend
  children:
    - row: laptops
      column: rev
      kind: Text
      spec:
        dataset: laptop-revenue
        value: "${data['laptop-revenue'][0].total_revenue} EUR"
    - row: laptops
      column: trend
      kind: ChartTime
      ref: laptop-trend-chart
    - row: tablets
      column: rev
      kind: Text
      spec:
        dataset: tablet-revenue
        value: "${data['tablet-revenue'][0].total_revenue} EUR"
    - row: tablets
      column: trend
      kind: ChartTime
      ref: tablet-trend-chart
```

Headers also accept a plain list of labels instead of the explicit `label`/`id`
objects (see [Header formats](#header-formats)), and a cell is either inline
(`kind` + `spec`) or a reference to a standalone document (`kind` + `ref`, see
[Child references and inline definitions](#child-references-and-inline-definitions)).

All attributes are listed in the [Attribute Reference](#attribute-reference) below.

## Fields

### Headers

| Field           | Type   | Default    | Description                                                                                           |
| --------------- | ------ | ---------- | ----------------------------------------------------------------------------------------------------- |
| `chartTitle`    | string | `""`       | Title displayed at the top-left of the grid.                                                          |
| `rowHeaders`    | array  | (required) | Row header definitions, at least one. Can be simple strings or objects with both `label` and `id`.    |
| `columnHeaders` | array  | (required) | Column header definitions, at least one. Can be simple strings or objects with both `label` and `id`. |

**Row and column headers** support two formats:

**Simple format** - Labels only, IDs are auto-generated as `0`, `1`, `2`, etc.:

```yaml
rowHeaders:
  - Electronics
  - Apparel
  - Home & Garden
columnHeaders:
  - Q1
  - Q2
  - Q3
```

**Explicit format** - Custom IDs for child references:

```yaml
rowHeaders:
  - label: Electronics
    id: electronics
  - label: Apparel
    id: apparel
columnHeaders:
  - label: Q1 2024
    id: q1
  - label: Q2 2024
    id: q2
```

### Display options

| Field               | Type    | Default  | Description                                                                                                                   |
| ------------------- | ------- | -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `showRowHeaders`    | boolean | `true`   | Whether to display the row headers column.                                                                                    |
| `showColumnHeaders` | boolean | `true`   | Whether to display the column headers row.                                                                                    |
| `showBorders`       | boolean | `true`   | Whether to display border/divider lines between cells.                                                                        |
| `rowHeaderWidth`    | string  | `"auto"` | CSS width of the row header column (e.g., `"auto"`, `"100px"`, `"20%"`).                                                      |
| `cellGap`           | string  | `"0px"`  | CSS gap between grid cells (e.g., `"0px"`, `"8px"`).                                                                          |
| `cellHeight`        | string  | `"auto"` | Height of the data rows: `auto` (each row fits its content) or `equal` (every row as tall as the tallest). See [Cell size and alignment](#cell-size-and-alignment). |
| `cellWidth`         | string  | `"auto"` | Width of the data columns: `auto` or `equal` (the grid fills its container and the columns share its width).                   |
| `cellVerticalAlign` | string  | `"top"`  | Vertical position of the content in its cell: `top`, `center`, `bottom` or `baseline`.                                        |
| `cellHorizontalAlign` | string | `"left"` | Horizontal position of the content in its cell: `left`, `center`, `right` or `baseline`.                                     |
| `selectedStyle`     | string  | -        | Name of a [`ComponentStyle`](/reference/component-style/) manifest to apply; merged over the `_system` and `_default` styles. |

### Children

| Field      | Type  | Description                                                                                   |
| ---------- | ----- | --------------------------------------------------------------------------------------------- |
| `children` | array | Array of child definitions, at least one. Each child specifies its grid position and content. |

Each child object has these properties:

| Property   | Type              | Required    | Description                                                                                                                       |
| ---------- | ----------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `row`      | string or integer | Yes         | Row identifier matching a row ID from `rowHeaders`. Can be string or integer.                                                     |
| `column`   | string or integer | Yes         | Column identifier matching a column ID from `columnHeaders`. Can be string or integer.                                            |
| `kind`     | string            | Yes         | Component type: `Text`, `Table`, `ChartStructure`, `ChartTime`, `ChartScatter`, `ChartBubble`, `ChartBullet`, `Tree`, or `Image`. |
| `ref`      | string            | No          | Reference to a standalone component document by name.                                                                             |
| `optional` | boolean           | No          | When `true`, skip gracefully if `ref` is missing (default: `false`).                                                              |
| `params`   | object            | No          | Parameter values (string map) passed to the referenced document. Only valid together with `ref`.                                  |
| `spec`     | object            | Conditional | Component specification. Required for inline children, optional override for `ref` children.                                      |
| `caption`  | string            | No          | Caption drawn at the top left of the cell, above its content.                                                                     |
| `metadata` | object            | No          | Optional metadata including `name` and `constraints`.                                                                             |

## Cell size and alignment

By default every row is as tall as its content, every column as wide as its content, and the content sits at the top left of its cell. Charts of different heights then start at the same top line, but their axes do not line up. Four fields change this:

- `cellHeight: equal` makes every data row as tall as the tallest, `cellWidth: equal` makes the grid as wide as its container and gives every data column the same share of it. Header rows and the row header column keep their size.
- `cellVerticalAlign` puts the content at the `top`, `center` or `bottom` of its cell, or on the `baseline` of its row.
- `cellHorizontalAlign` puts the content at the `left`, `center` or `right` of its cell, or on the `baseline` of its column.

With `baseline`, the grid moves the content of each cell so the baselines of a row (or a column) are on one line. The baseline of a component is:

| Component                                                 | Baseline                                                                                                           |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ChartTime`, `ChartStructure`, `ChartBullet`              | The axis line of the base segment: its height for a horizontal axis, its left end for the other direction.         |
| `ChartScatter`, `ChartBubble`                             | The x axis (bottom of the plot) and the y axis (left edge of the plot).                                            |
| `Table`                                                   | The bottom of the header, and the left edge of the first value column.                                             |
| `Text`, `Tree`, `Image`                                   | None. The content goes to the bottom of the cell (vertical) or stays left (horizontal).                            |

This also works when some charts have negative values and their axis is above the bottom. A table can be aligned to a chart in the same row or column.

A `caption` on a child draws a short text at the top left of the cell, above the content. Its font is set with the `caption*` keys of the [grid style](/reference/component-style/#grid-style-bn-grid).

```yaml
apiVersion: bino.bi/v1alpha1
kind: Grid
metadata:
  name: profit-by-region
spec:
  chartTitle: Net profit by region
  rowHeaders: [Top, Bottom]
  columnHeaders: [Left, Right]
  showRowHeaders: false
  showColumnHeaders: false
  cellHeight: equal
  cellWidth: equal
  cellVerticalAlign: baseline
  cellHorizontalAlign: baseline
  children:
    - row: 0
      column: 0
      kind: ChartTime
      ref: profit-trend
      caption: North
      spec: { filter: "rowGroup = 'North'", scale: "0.5" }
    - row: 0
      column: 1
      kind: ChartTime
      ref: profit-trend
      caption: South
      spec: { filter: "rowGroup = 'South'", scale: "0.5" }
    - row: 1
      column: 0
      kind: Table
      ref: profit-table
      caption: All regions
    - row: 1
      column: 1
      kind: ChartTime
      ref: profit-trend
      caption: West
      spec: { filter: "rowGroup = 'West'", scale: "0.5" }
```

A chart with `scale` unset or `auto` picks its font size from the size of its cell. With `cellWidth: equal` the cell width is a share of the grid width, so charts with different content get different factors. Pin `scale` when the charts must be comparable.

These fields and `caption` need template engine **v1.0.0-next.32** or newer. With an older engine `bino build` and `bino lint` stop with `grid-cell-layout-engine-version`, and `bino preview` shows that error. A grid without them keeps working on its engine.

## Child references and inline definitions

Grid children can reference existing component documents or define components inline.

### Reference to existing component

```yaml
children:
  - row: electronics
    column: q1
    kind: ChartStructure
    ref: electronics-q1-chart
```

If the referenced document declares parameters in `metadata.params`, pass values with `params` (see [LayoutPage parameters](/guides/layoutpage-params/#parameters-on-referenced-components)):

```yaml
children:
  - row: electronics
    column: q1
    kind: ChartStructure
    ref: quarterly-chart
    params:
      QUARTER: "q1"
```

### Inline component definition

```yaml
children:
  - row: electronics
    column: q2
    kind: Table
    spec:
      dataset: sales-data
      scenarios: ac,fc
```

### Reference with overrides

Combine a reference with inline spec to override specific properties:

```yaml
children:
  - row: electronics
    column: q3
    kind: ChartStructure
    ref: electronics-base-chart
    spec:
      chartTitle: Q3 Electronics # Override the base chart's title
      filter: quarter == 'Q3' # Add a filter
```

### Optional references

Mark a reference as optional to skip the child gracefully if the referenced component doesn't exist:

```yaml
children:
  - row: home
    column: q3
    kind: Table
    ref: home-q3-table
    optional: true # Skip if not found instead of erroring
```

## Constraint-based children

Children can include constraints that determine if they appear based on artefact labels, spec fields, or execution mode:

```yaml
children:
  - row: electronics
    column: q1
    kind: ChartStructure
    ref: detailed-chart
    metadata:
      name: detailed-electronics-q1
      constraints:
        - mode == build
        - labels.detail == high
  - row: electronics
    column: q1
    kind: Text
    spec:
      value: "Summary view"
    metadata:
      name: summary-electronics-q1
      constraints:
        - mode == preview
```

## Using Grid in layouts

Grid can be used as a child component in `LayoutPage` or `LayoutCard`:

### Standalone Grid document

With simple headers, use integers for row/column references:

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: Grid
metadata:
  name: sales-matrix
spec:
  rowHeaders: [North, South, East, West]
  columnHeaders: [Revenue, Units, Margin]
  children:
    - row: 0
      column: 0
      kind: Text
      spec:
        dataset: north-revenue
        value: "${data['north-revenue'][0].revenue}"
    - row: 0
      column: 1
      kind: Text
      spec:
        dataset: north-units
        value: "${data['north-units'][0].units}"
    # ... more children
```

### Reference in LayoutPage

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: LayoutPage
metadata:
  name: dashboard
spec:
  pageLayout: full
  children:
    - kind: Grid
      ref: sales-matrix
```

### Inline Grid in LayoutPage

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: LayoutPage
metadata:
  name: dashboard
spec:
  pageLayout: full
  children:
    - kind: Grid
      metadata:
        name: inline-grid
      spec:
        chartTitle: Inline Grid Example
        rowHeaders: [A, B]
        columnHeaders: [X, Y]
        children:
          - row: 0
            column: 0
            kind: Text
            spec:
              value: "Cell A-X"
          - row: 1
            column: 1
            kind: Text
            spec:
              value: "Cell B-Y"
```

## Complete example

A product comparison grid with multiple component types:

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: Grid
metadata:
  name: product-comparison
  description: Quarterly product performance comparison
spec:
  chartTitle: Product Performance Matrix
  rowHeaders:
    - label: Laptops
      id: laptops
    - label: Tablets
      id: tablets
    - label: Phones
      id: phones
  columnHeaders:
    - label: Revenue
      id: rev
    - label: Units Sold
      id: units
    - label: Trend
      id: trend
  showRowHeaders: true
  showColumnHeaders: true
  showBorders: true
  rowHeaderWidth: 120px
  cellGap: 4px
  children:
    # Laptop row
    - row: laptops
      column: rev
      kind: Text
      spec:
        dataset: laptop-revenue
        value: "${data['laptop-revenue'][0].total_revenue} EUR"
    - row: laptops
      column: units
      kind: Text
      spec:
        dataset: laptop-units
        value: "${data['laptop-units'][0].units_sold}"
    - row: laptops
      column: trend
      kind: ChartTime
      ref: laptop-trend-chart

    # Tablet row
    - row: tablets
      column: rev
      kind: Table
      ref: tablet-revenue-table
    - row: tablets
      column: units
      kind: Text
      spec:
        dataset: tablet-units
        value: "${data['tablet-units'][0].units_sold}"
    - row: tablets
      column: trend
      kind: ChartTime
      ref: tablet-trend-chart

    # Phone row
    - row: phones
      column: rev
      kind: ChartStructure
      ref: phone-revenue-chart
    - row: phones
      column: units
      kind: Text
      spec:
        dataset: phone-units
        value: "${data['phone-units'][0].units_sold}"
    - row: phones
      column: trend
      kind: ChartTime
      ref: phone-trend-chart
```

## Styling

Grid appearance is controlled via [`ComponentStyle`](/reference/component-style/) under the `bn-grid` key:

```yaml
apiVersion: bino.bi/v1alpha1
kind: ComponentStyle
metadata:
  name: custom-style
spec:
  content:
    bn-grid:
      headerBackground: "#f5f5f5"
      borderColor: "#cccccc"
      borderWidth: 1
      cellPadding: 8
```

See [ComponentStyle](/reference/component-style/) for all available grid styling options.

#### Header formats

**Simple format** - labels only, IDs are auto-generated:

```yaml
spec:
  rowHeaders: [Electronics, Apparel, Home]
  columnHeaders: [Q1, Q2, Q3]
```

**Explicit format** - custom IDs for child references:

```yaml
spec:
  rowHeaders:
    - label: Electronics
      id: electronics
    - label: Apparel
      id: apparel
  columnHeaders:
    - label: Q1 2024
      id: q1
    - label: Q2 2024
      id: q2
```

#### Grid child object

```yaml
spec:
  children:
    - row: electronics # must match rowHeaders ID
      column: q1 # must match columnHeaders ID
      kind: ChartStructure # see the kind values below
      ref: my-chart # optional reference to standalone document
      optional: false # skip gracefully if ref is missing
      spec: # inline spec or override for ref
        chartTitle: "Q1 Sales"
      metadata: # optional metadata
        name: cell-name
        constraints:
          - mode==build
```

| Property              | Type              | Required    | Default | Description                                                                                                                            | Sample                          |
| --------------------- | ----------------- | ----------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `children[].row`      | string or integer | yes         | -       | Row identifier matching a row ID from `rowHeaders` (or the auto-generated index).                                                      | `row: electronics`              |
| `children[].column`   | string or integer | yes         | -       | Column identifier matching a column ID from `columnHeaders` (or the auto-generated index).                                             | `column: q1`                    |
| `children[].kind`     | string            | yes         | -       | Component type. Values: `Text`, `Table`, `ChartStructure`, `ChartTime`, `ChartScatter`, `ChartBubble`, `ChartBullet`, `Tree`, `Image`. | `kind: ChartStructure`          |
| `children[].ref`      | string            | no          | -       | Reference to standalone document by name (`metadata.name`). The referenced spec is used as the base.                                   | `ref: electronics-q1-chart`     |
| `children[].optional` | boolean           | no          | `false` | Skip gracefully if `ref` is missing.                                                                                                   | `optional: true`                |
| `children[].params`   | object of string  | no          | -       | Parameter values passed to the referenced document, expanded as `${NAME}` in its spec. Only valid together with `ref`.                 | `params: { QUARTER: "q1" }`     |
| `children[].spec`     | object            | conditional | -       | Component specification. Required for inline children, optional override for `ref` children.                                           | `spec: { dataset: sales-data }` |
| `children[].caption`  | string            | no          | -       | Caption drawn at the top left of the cell, above its content. Needs engine v1.0.0-next.32.                                             | `caption: North`                |
| `children[].metadata` | object            | no          | -       | Optional metadata including `name` and `constraints`.                                                                                  | `metadata: { name: cell-name }` |
