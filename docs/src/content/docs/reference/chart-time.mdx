`ChartTime` manifests describe time-based charts.
They share many fields with `ChartStructure` but add date-axis-specific options.

## Minimal definition

The smallest well-formed `ChartTime` sets the required `spec.dataset` plus the fields
that give the chart a message: a title, the axis granularity, and the scenario columns
with their scale and unit. Scenarios are detected from the dataset when left blank, but
the detection emits a warning, so pinning them keeps the chart stable when the data
changes.

```yaml
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: revenue_monthly_chart
spec:
  dataset: revenue_monthly
  chartTitle: "Monthly revenue"
  dateInterval: month
  scenarios: ["ac1", "pp1", "fc1"]
  measureScale: M
  measureUnit: "EUR"
```

All attributes are listed in the [Attribute Reference](#attribute-reference) below.

The same chart renders as a line instead of columns with `chartMode: line`, and as
stacked columns or a stacked area with the `stack` block (see
[Stack configuration](#stack-configuration)).

## Fields

- `dataset` - required; a dataset name, an inline `DataSet` definition, or an array of those.
- `chartTitle` - optional title.
- `chartMode` - rendering mode: `bar` (default), `line`, or `auto`. When set to `auto`, the chart automatically switches to line mode when data points exceed `maxBars`.
- `maxBars` - threshold for auto-switching to line mode (default: 28). Only applies when `chartMode` is `auto`.
- `lineFullWidth` - when `true` (default in the renderer), line charts stretch to fill the full parent width instead of using fixed per-data-point spacing. Has no effect in bar mode.
- `axisLabelsMode` - how the date labels along the time axis are written. `smart` (default) prints only the part that changed since the previous label, so the year appears only where a new year starts; `long` and `short` use the long or the short date style for every label; `two-row` prints short labels and puts the year of a month, quarter or week in a second row, under the first period and where it changes. The short year label follows the translation key [`bn-chart-time.date-format-short-year`](/reference/internationalization/#time-and-structure-charts-bn-chart-time-bn-chart-structure-prefixes).
- `axisLabelsStep` - print only every n-th category label, starting with the first period. `2` labels every second period. Default: `1`. Bar mode only.
- `axisTitlePosition` - where the axis title stands: the chart title, or the name of a variance. `left` (default), `right` or `none`.
- `dataFormatDigitsDecimal` - number of decimal digits of the value labels. Default: `1`. Same meaning as on a [`Table`](/reference/table/).
- `dataFormatDigitsPercent` - number of decimal digits of the percent labels of relative variances. Default: `2`. Same meaning as on a `Table`.
- `dataFormatPercentSign` - `false` prints the labels of relative variances without the percent sign: `+11.6` in place of `+11.6%`. Default: `true`. Needs template engine v1.0.0-next.60.
- `scalingIndicator` - a value on the scale of the columns. The chart draws a light band behind the columns from the axis up to this value and prints the value at the right end. Two charts with different scales that show the same value make the difference visible. Bar mode only, not for a 100% stack. Needs template engine v1.0.0-next.60.
- `totals` - total columns at their own scale: one for all periods, or one per year, quarter, month or week. See [Totals](#totals). Needs template engine v1.0.0-next.64.
- `varianceWaterfall` - draws each row of absolute variances as a walk, and with totals at the scale of the chart as a bridge between the totals. Default: `false`. See [Variance waterfall](#variance-waterfall). Needs template engine v1.0.0-next.68.
- `referenceColumn` - with `scenarioSwitch`: draws the reference (the first scenario that is not part of the series) as a column behind the series, in place of the marker. Further scenarios stay markers. Default: `false`. Needs template engine v1.0.0-next.68.
- `scenarioSwitch` - for a series that changes its scenario along the time axis, for example AC up to this year and PL after it. Default: `false`. See [Scenario switch](#scenario-switch).
- `dateInterval` - desired time granularity; `auto` lets the renderer choose based on dataset meta.
- `filter` - optional filter expression.
- `measureScale`, `measureUnit` - SI prefix and unit string.
- `showCategories`, `showMeasureScale` - visibility flags.
- `showOverlayAvg`, `showOverlayMedian` - enables overlay lines.
- `intervalSpanLimit` - controls how many columns drive automatic date interval selection.
- `unitScaling` - data units displayed per 1 em of bar height (map-scale semantics: larger value = smaller bars), `auto` to fit the available height, or the name of a [ScalingGroup](/reference/scaling-group/). Unset or invalid values auto-fit with a warning that reports the resolved value.
- `percentageScaling` - percentage points per 1 em of pin/bar length for relative variances (`10` → a +10 % pin is 1 em long); same `auto`/group-name options.
- `syncSpaceLeft` - space reserved left of the axis for the scenario labels and the chart title, in px. `-1` (default) measures the widest label. Set the same value on several charts to align their axes; a value smaller than the widest label clips it.
- `scenarios` - list of scenarios (up to 4); values like `ac1`-`ac4`, `fc1`-`fc4`, `pp1`-`pp4`, `pl1`-`pl4`, or `auto`. When set to `auto`, scenarios are detected from the dataset silently. When left blank, they are detected with a warning. An empty list (`scenarios: []`) draws no scenario: the chart shows only its variances, see [Variance only chart](#variance-only-chart).
- `variances` - list of variance definitions of the form `d<scenarioB>_<scenarioA>_[pos|neg|neu|op|opinv]`. The values of a chart already carry their sign, so `_op` acts like `_pos` and `_opinv` like `_neg`. `_op` and `_opinv` need template engine v1.0.0-next.34 or newer. See [Variance sentiment](/reference/table/#variance-sentiment).
- `scale` - proportional scaling of the chart (font size, spacings, and bar/column dimensions all scale together). Scaling triggers on **width** overflow (horizontal axis labels cut off).
  - _not set_ - auto-scale to fit the parent width; emits an `AUTO_scale` warning with the applied factor. An empty string is not a valid value; omit the key instead.
  - `"none"` - no scaling; render at the base font size regardless of available space.
  - `"auto"` - auto-scale to fit the parent width silently (no warning).
  - `"0.5"`, `"1.2"`, … - fixed factor applied to the base font size. All dimensions scale proportionally.
- `stack` - optional object to enable stacked rendering:
  - `by` - (required) stacking dimension. `scenarios` stacks up to four scenario slots end-to-end. `dimensions` stacks one segment per value of the dataset column `category`, see [Stack by series](#stack-by-series).
  - `notation` - `scenario` gives each segment the look of its scenario. Default: `none`.
  - `legend` - where the series names stand: `left` (default), `right`, `both` or `none`.
  - `percentMark` - for `mode: relative`: plain shares and one `100%` mark. Default: `false`.
  - `mode` - stacking mode: `absolute` (additive, default), `relative` (100% stacked), or `absolute-relative` (absolute height with percentage labels).
  - `order` - segment order within each stack: `asc`, `desc`, or `dataset` (default).
  - When `chartMode` is `bar`, produces stacked columns. When `chartMode` is `line`, produces a stacked area chart.
- `i18nNamespace` - optional namespace consulted for this component's labels; missing keys fall back to `_system`. When not set, it is resolved from the nearest ancestor carrying one.
- `selectedStyle` - optional name of a [`ComponentStyle`](/reference/component-style/) to apply; merged over the `_system` and `_default` styles.
- `ruleset` - optional name of a [`RuleSet`](/reference/ruleset/) to apply, or `inherited-closest` / `inherited-page` to inherit the surrounding layout's rule set; merged over the `_system` and `_default` rule sets.

`level`, `order`, `orderDirection` and `limit` are still accepted, but have no effect: a time chart always shows one value per period, in date order. bino does not pass them to the template engine, and `bino lint` reports them with [`chart-time-field-no-effect`](/appendix/lint-rules/#chart-time-field-no-effect).

## Example: Short axis date labels

Write every axis label in the short date style instead of the default `smart` mode:

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: revenue_monthly_short_labels
spec:
  dataset: revenue_monthly
  chartTitle: "Monthly revenue"
  axisLabelsMode: short
  dateInterval: month
  scenarios: ["ac1"]
  measureScale: M
  measureUnit: "EUR"
```

With `dateInterval: month` the axis reads `Jan`, `Feb`, `Mar`, … on every column and never
shows the year. The default `smart` writes the same labels but adds the year where a new one
starts (`Jan 26`), and `long` writes `Jan 2026` on every column, which needs much more width.

### Line chart features

When rendered in line mode:

- Square markers (8×8px) at each data point
- Data values displayed above each marker
- Scenario labels positioned to the right of the last data point
- Smart X-axis labels showing start, end, and year boundaries
- Vertical dashed separator lines at year transitions
- IBCS color schema:
  - **AC (Actual)**: Black fill, black stroke, solid line
  - **PP (Previous Period)**: Gray fill, gray stroke, solid line
  - **FC (Forecast)**: White fill, black stroke, dashed line
  - **PL (Plan)**: White fill, black stroke, solid line

### Overdrive bars (overflow handling)

When `unitScaling` is set to a fixed numeric value (not `auto`), bars may exceed the
available container height. Instead of silently clipping the bars, the renderer applies
**overdrive rendering**:

1. **Base section** - the bar is drawn up to a computed cut height that fits within the container.
2. **Break indicator** - a zigzag line across the bar width signals the axis break.
3. **Overdrive section** - a proportionally scaled continuation above the break shows how much the bar exceeds the cut point.

Bars that fit within the available space render normally.
Among overflowing bars, the overdrive height is proportional to the overflow amount,
so a bar overflowing by 200 px gets twice the overdrive of one overflowing by 100 px.

AC scenario bars break at a higher point than PP, FC, and PL bars.
This staggered break position maintains the IBCS visual hierarchy between scenario types.

Overdrive bars apply to bar mode only and do not affect line charts, stacked charts, or auto-fit scaling.
The existing overflow warning is still emitted alongside the visual treatment.

### Cut of a large relative variance

A relative variance above 145 % is cut, so one outlier does not take the whole height. When `percentageScaling` is a fixed number, the pin is cut only when the full pin does not fit the available height. A pin that fits is drawn in full length. With `percentageScaling: auto` or without `percentageScaling`, the cut at 145 % stays. This needs template engine **v1.0.0-next.46** or newer. Older engines cut at 145 % in every case.

## Scenario switch

A plan often continues the actual values: AC up to this year, PL after it. In the data these are two scenarios, each with values in its own periods. Without `scenarioSwitch` the chart draws them as two series, and every period has a gap for the scenario without a value.

With `scenarioSwitch: true` the chart draws one series:

- A scenario that only has values in periods where the first scenario has none is drawn in its place, as a full column with value labels.
- A vertical line marks the change, and the scenario names stand under the axis.
- Variances of one type over the same reference share one row: `dac1_pp1_pos` and `dpl1_pp1_pos` are one row of variances from `pp1`. The plan variances are outlined. With template engine v1.0.0-next.60 the forecast variances are hatched, also the head of a forecast pin, and the row is named by the reference only (`ΔPY`).
- If two of them have a value in the same period, the first one wins and the chart warns.

A chart with exactly one scenario gets the name of that scenario under the axis.

It works in bar mode, without `stack` or with `stack.by: dimensions`. A stack by scenarios draws its scenarios on top of each other, so there is nothing to switch.

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: net_profit_actual_and_plan
spec:
  dataset: net_profit_yearly
  chartTitle: "Net profit"
  dateInterval: year
  scenarios: ["ac1", "pl1"] # ac1 has values up to 2026, pl1 from 2027
  variances: ["dac1_pp1_pos", "dpl1_pp1_pos"]
  scenarioSwitch: true
```

## Totals

Twelve months and their year do not fit on one scale: the year is about twelve times as high. `totals` adds total columns with their own `unitScaling`.

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: contribution_months_and_year
spec:
  dataset: contribution_monthly
  dateInterval: month
  unitScaling: 28
  scenarios: [ac1, fc1, pp1] # ac1 has values up to September, fc1 from October
  variances: [dac1_pp1_pos, dfc1_pp1_pos, drac1_pp1_pos, drfc1_pp1_pos]
  scenarioSwitch: true
  scalingIndicator: 100
  totals:
    by: all
    unitScaling: 280
    label: "2025"
    width: 1.6
```

**The scale: `unitScaling`**

`totals.unitScaling` gives the total columns their own scale. Leave it out and they use the scale of the chart (needs template engine v1.0.0-next.68). A total is then as high as the sum of its periods, so the chart needs the room.

**What a total covers: `by`**

- `all` (default): one column for all periods of the chart. It stands right of the last period, with a gap and its own axis. The names of its parts stand at its right.
- `year`, `quarter`, `month`, `week`: one column behind the periods of each year, quarter, month or week. It stands on the axis of the periods, and the periods after it move on. Its name is the name of its period. So twelve months get four quarter columns with `by: quarter`, and four weeks of days get four week columns with `by: week`.

**How the periods become one value: `aggregation`**

- `sum` (default): the column stacks one part per scenario of the series: the first scenario, and with `scenarioSwitch` the scenarios that follow it, each in its look. Each part prints its value, the total stands above.
- `average` and `last`: for a measure that cannot be added up, like a stock, a price or a ratio. The column is one value: the average of the periods, or the value of the last period with a value. It is hatched when a forecast is in the value and outlined for a plan.

**Values from the data: `dataset`**

With `dataset` the chart computes nothing. It takes the values from a `DataSet` with one row per total: a `date` and the scenario columns of the chart. A `0` counts as no value. With `aggregation: average` or `last` the values of a row are one column. A row belongs to the total whose period holds its date, with `by: all` every row counts. Use it when the total is not the sum of the periods shown, for example three months and the full year.

```yaml
totals:
  by: all
  dataset: contribution_year # date, ac1, pp1
  unitScaling: 600
  label: "2025"
```

**Scenarios at the total only: `scenarios`**

A total can show one more scenario that the periods do not show, for example the previous year next to a plan. List it in `totals.scenarios`. It must not be in `scenarios` of the chart ([`total-only-scenario`](/appendix/lint-rules/#total-only-scenario)). The chart adds it up from its dataset over the periods the total counts. A scenario with a gap in these periods has no value, like a reference. Needs template engine v1.0.0-next.69.

```yaml
scenarios: [ac1, pl1, fc1]
totals:
  by: all
  scenarios: [pp1] # the dataset has pp1 per month
```

With `dataset` the list is not needed: every scenario column of a row that the chart does not draw is shown at the total only. A list then limits them.

- In a [bridge](#variance-waterfall) the scenario is one more total column before the reference total, with its value and its name. Its variance to the total of the series is a thin bar right of the variance of the total.
- Without a bridge it is a column behind the total column. With `by: all` its variance stands right of the total column.

**In every case**

- The first other scenario is the reference. Its value is a column behind the total column. It counts in the periods where the series has a value, so a total of January to March stands against the reference of January to March.
- Each variance row gets the variance of each total, at the scale of the row. So the tiers of a total line up with the tiers of the periods. The variance is put together like the total: the sum, the average or the last value of the series against the same of the reference, over the periods where both have a value.
- With `scalingIndicator` a total column has its own band at its own scale. With `by: all` a line links it to the band of the periods.
- An [`Annotation`](/reference/annotation/) points at a total with `row: total`. With `by: all` there is no `date`: `point: { row: total, scenario: dac1_pp1_pos, part: label }` is the label of the total variance. With the other values `date` is the first day of the period of the total.
- With an older engine `bino lint` and `bino build` stop with [`time-totals-engine-version`](/appendix/lint-rules/#time-totals-engine-version). The same holds for `scalingIndicator` and `dataFormatPercentSign: false`.
- It works for plain columns: not with `stack`, not in line mode and not with `scenarios: []`. The chart needs a fixed `unitScaling`. Every part of a total must be positive: when one is not, the chart draws no total columns.
- A group where the series has no value gets no total. `by` must be coarser than the periods of the chart: `by: month` on a month chart gives no totals.

## Variance waterfall

With `varianceWaterfall: true` a row of absolute variances is a walk: each column starts where the column before ended, and thin lines join them. The row shows how the variance adds up over the periods. A period without a value keeps the level. Relative variances stay pins. With `scenarioSwitch` the variances of a forecast are hatched as before.

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: net_sales_bridge
spec:
  dataset: net_sales_monthly
  dateInterval: month
  unitScaling: 9
  scenarios: [ac1, pl1, fc1] # ac1 has values up to August, fc1 from September
  variances: [dac1_pl1_pos, dfc1_pl1_pos, drac1_pl1_pos, drfc1_pl1_pos]
  scenarioSwitch: true
  varianceWaterfall: true
  totals:
    by: all
    label: "2025"
    width: 1.6
```

**The bridge.** When the chart also has `totals` with `by: all`, `aggregation: sum` and no `unitScaling` of their own, the first row of absolute variances becomes a bridge in the chart itself:

- The reference total stands left of the first period, with its value and the name of its scenario.
- The total of the series stands right of the last period, as before.
- The walk starts at the end of the reference total and ends at the end of the total of the series.
- The variance of the total is a thin bar between the two levels, right of the total column. An `Annotation` points at its label with `point: { row: total, scenario: dac1_pl1_pos, part: label }`.

The other variance rows stay where they are. The chart draws the plain walk in its own row and warns when a bridge is not possible:

- the totals have their own `unitScaling`, another `by` or another `aggregation`,
- the total has no reference (the reference misses a value in a period of the series),
- the variances of the row are not the series against the reference of the total,
- `syncSpaceLeft` is set: the reference total has no room in a synced space,
- the reference total plus the variances is not the total of the series, for example with totals from a `dataset` that do not match the periods,
- the walk would cross the columns of the periods. This happens with few periods, when one period is a large part of the total.

A walk has no break marks. Behind a total column on the axis (`totals.by` other than `all`) a walk starts again. It works for plain columns: not with `stack` and not in line mode.

## Variance only chart

`scenarios: []` draws no scenario. The chart shows only its variances:

- The scenarios that the variances need are still read from the dataset.
- The first variance carries the category labels.
- `chartTitle` is not shown.
- Without `variances` the chart is empty and warns.

An empty list is not the same as a missing field. Without `scenarios`, or with `scenarios: auto`, the chart detects the scenarios from the dataset.

:::caution[Changed behaviour]
Up to Bino v0.110.0, `scenarios: []` on a `ChartTime` had the same effect as no `scenarios` at all: the scenarios were detected from the dataset. It was a way to clear a list that came from a `ref` or from a dataset default. Now an empty list means "no scenarios". To get the detection back, remove the field or write `scenarios: auto`. A `Table` is not changed: there an empty list still means detection.
:::

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: net_profit_variance_only
spec:
  dataset: net_profit_yearly
  dateInterval: year
  scenarios: []
  variances: ["dac1_pp1_pos"]
```

The fields of this section, `axisLabelsStep`, `axisTitlePosition` and the two `dataFormatDigits*` fields need template engine **v1.0.0-next.46** or newer. Older engines ignore them. So with an older engine `bino build` and `bino lint` stop with [`small-multiple-span-engine-version`](/appendix/lint-rules/#small-multiple-span-engine-version). A chart that leaves them at their defaults keeps working on its engine. The check also sees a field that a [dataset default](/reference/dataset/#dataset-defaults) sets.

:::caution[Dataset defaults]
`dataFormatDigitsDecimal` and `dataFormatDigitsPercent` were `Table` fields only. A dataset default for every kind, `_spec_any_dataFormatDigitsDecimal` or `constants.spec.any.dataFormatDigitsDecimal` (and the same for `Percent`), now also reaches a `ChartTime` that binds this dataset as its primary dataset. To keep the digits on tables only, use the table default: `_spec_table_dataFormatDigitsDecimal` or `constants.spec.table.dataFormatDigitsDecimal`. See [Dataset defaults](/reference/dataset/#dataset-defaults).
:::

## Example: Stacked columns by scenario

Stack AC and PP values as additive columns:

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: revenue_stacked_chart
spec:
  dataset: revenue_monthly
  chartTitle: "Revenue stacked by scenario"
  dateInterval: month
  unitScaling: 267
  scenarios: ["ac1", "pp1"]
  stack:
    by: scenarios
    mode: absolute
```

## Stack by series

`stack.by: dimensions` takes the series from the dataset. Each value of the `category` column is one segment. The order comes from `categoryIndex`. There is no limit of four series, and a series keeps its colour in every period, also when it has no value there. Needs template engine v1.0.0-next.49: older engines draw one segment per period.

The dataset has one row per period and series. The scenario is the slot that holds the value:

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: DataSet
metadata:
  name: sales_by_area
spec:
  query: |
    SELECT make_date(year, 1, 1) AS date, area AS category, area_index AS categoryIndex,
      CASE WHEN scenario = 'AC' THEN value END AS ac1,
      CASE WHEN scenario = 'PL' THEN value END AS pl1
    FROM sales
  dependencies: [sales]
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: sales_by_area_chart
spec:
  dataset: sales_by_area
  dateInterval: year
  scenarios: [ac1, pl1]
  scenarioSwitch: true
  stack:
    by: dimensions
    notation: scenario
    legend: left
```

- With `scenarioSwitch: true` each period stacks the scenario that has values there. One axis can go from AC to FC to PL, with the line at the change and the names under the axis. Without it only the first scenario is drawn.
- One period can mix scenarios (needs template engine v1.0.0-next.60). A series without a value in the scenario of the period takes the scenario that has its value. So a year can be one column with the actual months as the first series and the forecast months as the second, hatched with `notation: scenario`. A scenario with values for the same series as the visible one is the reference: the chart draws its total as a column behind the stack. A 0 counts as no value here.
- `notation: scenario` marks the scenario on every segment. A forecast segment is hatched over the shade of its series and a plan segment is outlined. The first series takes the fill of the scenario from `barStyles`, so it is white in a forecast and in a plan.
- `legend` puts the series names left of the first column, right of the last column with a value, at both sides, or nowhere.
- The shades come from `stackColors` of the `bn-chart-time` style. Give it one colour per series.
- For a 100% stack, set `mode: relative` and `percentMark: true`. The segment labels are the shares as plain numbers with `dataFormatDigitsPercent` digits, and one `100%` mark stands at the top of the stack on the side of the names.
- With `axisLabelsMode: two-row` a month chart prints the year in the second row, together with the scenario name: `2025 AC`.

An [`Annotation`](/reference/annotation/) can point at one segment with `date` and `category`.

## Example: Stacked area chart

Combine `chartMode: line` with `stack` to render stacked area fills:

```yaml
---
apiVersion: bino.bi/v1alpha1
kind: ChartTime
metadata:
  name: revenue_stacked_area
spec:
  dataset: revenue_monthly
  chartTitle: "Revenue trend (stacked area)"
  chartMode: line
  dateInterval: month
  unitScaling: 267
  scenarios: ["ac1", "pp1", "fc1"]
  stack:
    by: scenarios
    mode: absolute
```

## Inherited props

Instead of repeating `scenarios` and `variances` on every component, you can inherit them from an ancestor `LayoutPage` or `LayoutCard`. Set either of them to a special keyword:

| Value               | Resolves from                                                     |
| ------------------- | ----------------------------------------------------------------- |
| `inherited-closest` | Nearest ancestor `LayoutCard` or `LayoutPage` that sets the field |
| `inherited-page`    | Nearest ancestor `LayoutPage` only (skips cards)                  |

The inherited value is read from the ancestor's corresponding `titleScenarios` or `titleVariances` field. With `inherited-closest`, a `LayoutCard` that does not set the field is skipped and the lookup continues outwards to the `LayoutPage`. Template engines before **v1.0.0-next.28** ask only the nearest card or page.

A keyword cannot be resolved when the page (and, for `inherited-closest`, every enclosing card) does not set the matching field. From template engine **v1.0.0-next.28** on, the component then behaves as if the field were not set (scenarios are auto-detected) and shows a warning. Older engines keep the keyword as a literal value: nothing is auto-detected and the component renders without usable scenarios. `bino lint` reports this case with the rule [`inherited-prop-unresolved`](/appendix/lint-rules/#inherited-prop-unresolved).

```yaml
children:
  - kind: ChartTime
    spec:
      dataset: revenue_trend
      dateInterval: month
      scenarios: inherited-page # uses page's titleScenarios
      variances: inherited-page # uses page's titleVariances
```

See the [ChartStructure inherited props](/reference/chart-structure/#inherited-props) section for full examples.

#### Stack configuration

```yaml
spec:
  stack:
    by: scenarios # scenarios | dimensions
    mode: absolute # absolute | relative | absolute-relative
    order: dataset # asc | desc | dataset
```

| Property      | Type   | Required | Default    | Description                                                                                                                 |
| ------------- | ------ | -------- | ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| `stack.by`    | string | yes      | -          | Stacking dimension. `scenarios`: stacks scenario slots end-to-end. `dimensions`: only the first scenario is drawn.          |
| `stack.mode`  | string | no       | `absolute` | Stacking mode. `absolute`: additive. `relative`: 100% stacked. `absolute-relative`: absolute height with percentage labels. |
| `stack.order` | string | no       | `dataset`  | Segment order within each stack. Values: `asc`, `desc`, `dataset`.                                                          |
