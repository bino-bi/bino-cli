`bino registry` manages packages consumed from a bino registry.
Dependencies are declared in `bino.toml`'s `[dependencies]` table, resolved
versions are pinned in `bino.lock` (commit it), and package files are
materialized under `.bino/registry/` (gitignore it - `bino registry install`
re-creates it from `bino.lock`).

See the [Registry and dependencies guide](/guides/registry-and-dependencies/)
for the underlying concepts: package names, pin vs. tag semantics, the
lockfile, and authentication. The registry URL resolution order (project
config, environment, global `~/.bino/config.toml`, public default) is
described there as well.

The same operations are available to AI agents through the [MCP server](/cli/mcp/#registry) -
`registry_search`, `registry_info`, `registry_packages`, `registry_add`, `registry_update`,
`registry_remove` and `registry_install` mirror the commands below. Accepting a
new package signer is left to a human: there is no MCP tool for
`bino registry trust accept`.

`add`, `update` and `install` verify the signatures the registry serves for a
package and apply the [trust policy](/reference/trust-policy/) and the signer
pinned in `bino.lock`. A package whose signer changed, or that the policy
rejects, fails the command and nothing is written.

## bino registry add

```bash
bino registry add <package[@version|@tag]>...
```

Resolves each package (and its transitive dependencies), downloads the
verified documents into `.bino/registry/`, pins the result in `bino.lock`,
and records the dependency in `bino.toml`.

- A bare package name follows the `latest` tag; `@1.2.3` pins that exact version.
- Prints compatibility warnings when a package declares a CLI or engine range that does not match your setup.

```bash
# Follow the latest tag
bino registry add @acme/base-layout

# Pin an exact version
bino registry add @acme/quarterly-report@1.2.3
```

## bino registry install

```bash
bino registry install
```

Re-materializes `.bino/registry/` from `bino.lock` without re-resolving
anything, so CI and fresh checkouts reproduce the exact locked versions.

- Errors when `bino.toml` declares dependencies but no `bino.lock` exists, or when the lockfile drifted from `[dependencies]` - run `bino registry update` in both cases.

## bino registry update

```bash
bino registry update [package...]
```

Re-resolves the dependencies declared in `bino.toml` and rewrites `bino.lock`.
Entries that follow a tag move with it; exact-version pins are held. With
package arguments, only those packages are re-resolved and every other direct
dependency is held at its locked version.

## bino registry remove

```bash
bino registry remove <package>...
```

Removes packages from `bino.toml`'s `[dependencies]` table, then deletes every
locked package no longer reachable from the remaining declarations. Works
offline. A transitive dependency still required by another package is kept.

## bino registry list

```bash
bino registry list
```

Lists the packages pinned in `bino.lock` with version, tag, kinds, file count,
origin (direct or transitive), and the package's primary document. Works
offline.

## bino registry search

```bash
bino registry search <query> [flags]
```

Searches the registry for packages.

- `--kind` - filter by document kind (repeatable).
- `--scope` - filter by scope (repeatable).
- `--tag` - filter by tag (repeatable).
- `--page` - result page, 1-based (default 1).
- `--per-page` - results per page (default 20).

## bino registry info

```bash
bino registry info <package[@version|@tag]>
```

Shows a package's resolved metadata: version, tag, kinds, digest, compat
ranges, dependencies, the signatures the registry reports for the version,
and the files the version ships. Requires network access. The signature lines
are the registry's own claim; `add`, `update` and `install` verify the
signatures themselves.

## bino registry verify

```bash
bino registry verify
```

Re-hashes every package file under `.bino/registry/` and compares it with the
digest pinned in `bino.lock`. Works offline; intended as a CI gate. Manifest
digests are computed over the canonical document form, so cosmetic reformatting
of a file does not fail verification; resources are hashed over their raw bytes.
A file inside a package directory that `bino.lock` does not record is reported
as `EXTRA`.

It also re-checks, offline, the signatures stored at install time under
`.bino/registry/.attestations/` against the signer pinned in `bino.lock` and the
[trust policy](/reference/trust-policy/). The statuses are `SIGNER MISMATCH`
(the stored signature is by another signer), `SIGNATURE MISSING` (the lock pins
a signer but no signature is stored), `INVALID SIGNATURE` and `UNTRUSTED` (the
policy rejects the package). Exits non-zero on any failure.

## bino registry trust accept

```bash
bino registry trust accept <package[@version|@tag]>
```

Once `bino.lock` records who signed a package, a version signed by someone
else, or not signed at all, fails at every `[trust]` require level. If the
change is expected, this command resolves the package, verifies its signature,
and pins the new signer in `bino.lock`. It prints the old and the new signer.
The trust policy still applies; only the pin is waived.

Without a version, a declared dependency is re-resolved like
`bino registry update <package>`, and a transitive one through the declared
dependencies that pull it in. With a version or tag, a declared dependency
moves to it like `bino registry add`.

```bash
bino registry update
# Error: package signer changed: @acme/kit was signed by ..., but 2.0.0 is signed by ...
bino registry trust accept @acme/kit
```

To publish a package rather than consume one, see [bino publish](/cli/publish/).

## bino registry login

```bash
bino registry login [flags]
```

Stores a personal access token in `~/.bino/credentials.json` (mode 0600).
Subsequent registry commands use the stored token automatically unless
`bino.toml` or `BINO_REGISTRY_TOKEN` provides one.

Personal access tokens are created and managed in the registry web UI
(Settings → Tokens) - create one there first, then paste it when prompted.

- `--registry` - registry URL (overrides `bino.toml`, `BINO_REGISTRY_URL`, and `~/.bino/config.toml`; default `https://registry.bino.bi`).
- `--with-token` - read the personal access token from stdin instead of prompting.

```bash
# Interactive: paste the token created in the web UI
bino registry login

# Non-interactive (CI)
echo "$BINO_PAT" | bino registry login --with-token
```

## bino registry logout

```bash
bino registry logout [--registry <url>]
```

Removes the stored credential for the registry and revokes it server-side
(best effort - the local credential is always removed).
