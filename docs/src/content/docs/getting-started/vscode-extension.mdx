# VS Code Extension

The Bino Reports VS Code extension provides schema-aware YAML editing, navigation, validation, preview, and dependency graph exploration for Bino report manifests.

Beyond YAML editing, the extension also ships a schema-driven **Designer**, a
**DataSource Wizard**, a **Tree Editor**, **Add Element**, build tasks, and SQL and
PRQL support inside `query:` / `prql:` blocks. See sections 7 and 9-13 below.

### Architecture

- **`bino lsp`** - a real [Language Server Protocol](/cli/lsp/) process, started
  automatically over stdio, provides live diagnostics, completion, hover,
  go-to-definition, find-references, rename, and quick-fixes.
- **`bino daemon`** - an optional persistent background process (enabled by
  default, see `bino.daemon.enabled`) that both the LSP and the extension's
  data/preview/build features share, so indexing, validation, and DuckDB
  column introspection stay warm across requests instead of paying a
  cold-start cost on every call.
- When the daemon is unavailable, the language server serves the project index,
  and data features (columns, rows, the dependency graph) fall back to discrete
  `bino lsp-helper <subcommand>` CLI calls.

### MCP server

The extension registers the daemon's [MCP server](/cli/mcp/) with VS Code, so agent mode in
VS Code chat can use the bino tools without any setup. It shows up as **Bino** in the MCP server
list (`MCP: List Servers`). VS Code connects to `http://127.0.0.1:<port>/mcp` and sends the token
from `.bino/daemon.json` as a Bearer token (see [The daemon port file](/cli/mcp/#the-daemon-port-file)).

The server is offered only while the daemon is connected: not with `bino.daemon.enabled` off,
and not in an untrusted workspace. When the daemon restarts on a new port, VS Code gets the new
address on its own.

If the extension shows "The running bino daemon rejected this extension", the daemon uses a
different token than the extension expects, usually because it comes from a newer bino. Click
**Restart Daemon**.

## 1. Prerequisites

Before installing the extension, make sure you have:

- **VS Code** 1.101.0 or newer (or an editor that installs from Open VSX, such as Cursor, Windsurf or VSCodium)
- **Bino CLI**: on your `PATH`, set in `bino.binPath`, or downloaded by the extension (see 3.2)

---

## 2. Installation

### 2.1 From the Marketplace

You can install the extension directly from the [VS Code Marketplace](https://marketplace.visualstudio.com/items?itemName=BinoBI.vscode-bino).

The same extension is published to [Open VSX](https://open-vsx.org/extension/BinoBI/vscode-bino), which Cursor, Windsurf and VSCodium use.

Alternatively:

1. Open the **Extensions** view in VS Code.
2. Search for **"Bino Reports"**.
3. Click **Install**.

The extension activates when the workspace contains a `bino.toml`, or when you open the **Bino Reports** view.

### 2.2 From a `.vsix` (local build)

If you are working from this repository and packaging the extension yourself:

```bash
cd vscode-bino
npm install
npm install -g @vscode/vsce
vsce package --out vscode-bino.vsix

code --install-extension ./vscode-bino.vsix
```

Then reload VS Code:

```text
Cmd+Shift+P → "Developer: Reload Window"
```

To uninstall a locally installed build:

```bash
code --uninstall-extension BinoBI.vscode-bino
```

## 3. First-Time Setup

The **Get Started with Bino** walkthrough (**Help > Welcome**, or
**Welcome: Open Walkthrough...**) has four steps: install bino, create a project
(**Initialize Project** runs `bino init`), add a DataSource with the wizard, and
start the preview.

Without a `bino.toml` in the workspace, the **Bino Reports** view shows **Getting
Started** with **Initialize Project**, **Check Setup** and **Open Folder**. Once a
`bino.toml` appears, the extension asks you to reload the window.

### 3.1 Check your setup

Run the **Bino: Check Setup** command:

1. Press `Cmd+Shift+P` / `Ctrl+Shift+P`.
2. Run **"Bino: Check Setup"**.

This command verifies:

- Whether the `bino` CLI can be found, and its version and path.
- Whether it has the language server (`bino lsp`).

If something is wrong, the command shows a detailed message.

### 3.2 Download bino

The extension looks for bino in this order: the `bino.binPath` setting, `bino` on
your `PATH`, then a bino that the extension downloaded.

**Bino: Download bino** (also a button in the walkthrough) gets the latest release
from GitHub, checks its SHA-256 checksum and keeps it in the extension's storage
folder. If another `bino` is on your `PATH`, it offers to set `bino.binPath` to the
download. Reload the window afterwards. Nothing is downloaded unless you click it.

When bino is missing, or older than the extension, the extension offers
**Download bino** at startup.

### 3.3 Workspace trust

Bino runs the SQL and YAML in the workspace, so in an untrusted workspace the
extension starts nothing: no daemon, language server, preview, build, or MCP
server. Commands show a message with **Manage Workspace Trust**. A `bino.binPath`
from the workspace settings counts only in a trusted workspace. Once you trust
the workspace, the features start without a reload.

### 3.4 Multi-root workspaces and nested projects

Every folder with a `bino.toml` is a project. The window works on one project at
a time: the project of the active file (the nearest `bino.toml` above it), else
the last current project, else the first one found. The language server, daemon,
index, preview and builds all follow it. When the current project changes, a
running preview restarts on the new project.

Run **Bino: Switch Project...** to pick the project yourself. With more than one
project, the status bar menu has the same entry.

## 4. Bino Views

The **Bino Reports** activity bar container (click the Bino icon in the Activity
Bar) holds four views:

- **Documents** (`binoDocuments`) - all indexed manifests, grouped by kind.
- **Preview & Build** (`binoPreview`) - preview, build, validate-with-queries and graph actions.
- **Dependencies** (`binoDependencies`) - the project's registry packages and their install state.
- **Environment** (`binoEnvironment`) - CLI/project info, diagnostics counts, and settings shortcuts.

**What you see in Documents:**

- Documents grouped by kind (ReportArtefact, DataSource, DataSet, LayoutPage, LayoutCard, Table, Text, etc.).
- Count badges on each kind group.
- Icons that reflect the manifest kind (database for DataSource, table for DataSet, PDF icon for ReportArtefact, etc.).
- Inline children for layouts (LayoutPage, LayoutCard) - nested Text/Table/Chart components.

### 4.1 Interactions

- **Click** a document to open it.
  - If the document has problems, the editor jumps to the first diagnostic.
  - Otherwise, it jumps to the start of that YAML document (supports multi-doc files).
- **Click** an inline child (component) to open the parent file and focus the correct line.
- **Toolbar** at the top of the Documents view:
  - **Add Element** - `bino.addElement` (see 13)
  - **Refresh Index** - `bino.refreshIndex`

### 4.2 Context Menu

Right-click on a document in the Bino Explorer to access:

- **Preview (Embedded)** and **Open Designer** (documents that render on their own: artefacts, tables, charts and the like).
- **Go to First Problem** - jumps to the first diagnostic in that file.
- **Show Graph (Dependencies & Dependents)** - opens a QuickPick built from the dependency graph.
- **Show Dependencies** - shows what this document depends on.
- **Show Dependents (What Uses This?)** - shows what uses this document.

## 5. Smart Editing Features

Completion, hover, diagnostics, and navigation are all served by the `bino lsp`
[Language Server](/cli/lsp/). It only answers in Bino YAML: other YAML files in
the workspace (CI, Compose, Kubernetes) stay silent.

### 5.1 Autocompletion

The extension provides completions in YAML files for:

- `dataset:` / `dependencies:` - suggests DataSet names and `$DataSource` references.
- `source:` - suggests DataSource names.
- `secret:` - suggests ConnectionSecret names.
- `signingProfile:` - suggests SigningProfile names.
- `selectedStyle:` - suggests defined ComponentStyle names.
- `kind:` fields - suggests all known Bino kinds, plugin kinds included.
- Scenario/variance references - suggests column names based on the referenced dataset/datasource.
- Inside `query:`/`prql:` blocks - see 12.

**Screenshot placeholder:**

```md
![VS Code completion placeholder](../assets/vscode-bino-completion-placeholder.png)
```

### 5.2 Go to Definition, Find References, Rename

Ctrl/Cmd+Click (or F12) on:

- `dataset:` / `dependencies:` values → jumps to the DataSet or DataSource.
- `source:` → DataSource.
- `secret:` → ConnectionSecret.
- `signingProfile:` → SigningProfile.
- `selectedStyle:` → ComponentStyle.
- `page:` / `layoutPages:` entries → LayoutPage.
- `ref:` (layout children) → the referenced component, resolved via its sibling `kind`.
- A name after `FROM` / `JOIN` in a query → its DataSet or DataSource.

Shift+F12 (**Find All References**) and F2 (**Rename Symbol**) work on any
`metadata.name` and update every reference site across the workspace, including
the name in the SQL of DataSets that read it. Quick fixes are offered for a
missing `${VAR}` in `.env`, a missing required schema field, a DataSource the
query reads but `spec.dependencies` does not list, or a dangling reference
(scaffolds the missing manifest).

Definitions/references are resolved from a live workspace name index and
support multi-document YAML and unsaved edits.

### 5.3 Hover Information

Hover over a dataset/datasource reference (or a name after `FROM` / `JOIN`) to
see its columns with their types and the first rows. A field shows its schema
description, and a scenario or variance token its IBCS meaning.

Columns are introspected live via DuckDB (through the `bino daemon` when
running) and cached until the project changes.

**Screenshot placeholder:**

```md
![VS Code hover placeholder](../assets/vscode-bino-hover-placeholder.png)
```

### 5.4 Inlay Hints and File Links

- After each `${NAME}`, an inlay hint shows the value it resolves to: a param
  default of the document, the environment, or `bino.toml` `[build.env]`, in the
  order the build reads them. Values of secret-looking names show as `****`.
- File paths (`$file`, `localPath`, `path`, `file`, `stylesheet`) are links to
  the file, when it exists.

### 5.5 bino.toml

The language server also checks `bino.toml`: syntax errors, wrong value types,
and keys the build ignores are shown as you type. It completes table names after
`[` and the keys of the current table. The extension also registers the
`bino.toml` JSON schema for TOML extensions that read it.

## 6. Validation

Live diagnostics are pushed continuously by the `bino lsp` [Language
Server](/cli/lsp/) as you type (schema errors, engine-constraint violations)
and, on every disk change, project-wide (lint findings, missing `${VAR}`
environment variables, engine-compat warnings). No manual step is required.

### 6.1 Validate with Queries

**Bino: Validate with Queries** (also in **Preview & Build**) runs
`bino lint --execute-queries` in the integrated terminal. To check queries on
save in the editor instead, turn on `bino.lsp.queryDiagnostics` (see 12).

### 6.2 Diagnostics in the Explorer

- Document items show badges when there are diagnostics.
- The **Go to First Problem** context menu item jumps directly to the first issue.

## 7. Preview and Build

### 7.1 Preview Server

The extension integrates with the `bino preview` command via a **Preview Manager**:

- Start: **Bino: Start Preview** (`bino.startPreview`)
- Stop: **Bino: Stop Preview** (`bino.stopPreview`)
- Restart: **Bino: Restart Preview** (`bino.restartPreview`)
- Open in browser: **Bino: Open Preview in Browser** (`bino.openPreviewInBrowser`)
- Open beside the editor: **Bino: Open Preview in Webview** (`bino.openPreviewInWebview`)
- One artefact or component: **Bino: Preview (Embedded)** (`bino.previewArtefactEmbedded`), also a CodeLens above each document that renders on its own

Both webviews follow the editor: when you move to another artefact (or, in the
embedded preview, another component), the preview switches to it. Editing a
dependency keeps the last one. The embedded preview also renders unsaved edits.

**Cmd/Ctrl-click** a component in the preview to open its source. A recent bino
goes to the exact line, an older one to the start of the document.

In a remote window (Codespaces, Dev Containers, WSL, Remote SSH), the preview
port is forwarded and the webview and browser use the forwarded address.

### 7.2 Status Bar

One **Bino** item in the status bar sums up the daemon, preview, index, and
diagnostics state: a spinner while busy, the error or warning count, and an eye
while the preview runs. The tooltip has the details (and the current project
when there is more than one). Click it for a menu:

- **Preview...** (the preview menu, also **Bino: Preview Menu**)
- **Restart Daemon** (when the daemon is enabled)
- **Switch Project...** (with more than one project)
- **Refresh Index**, **Show Problems**, **Open Log**, **Check Setup**, **Settings**

### 7.3 Build Tasks

Builds run as VS Code tasks of type `bino`: **Terminal > Run Build Task**, **Bino:
Build Report** (`bino.build`, all artefacts), or **Bino: Build Specific Artefact**
(`bino.buildArtefact`). The task list has one task for all artefacts and one per
artefact. A task runs `bino build --log-format json --no-color` (with
`--artefact <name>` for one artefact) in the project root.

You can also put the task in `tasks.json`:

```jsonc
{
  "version": "2.0.0",
  "tasks": [
    { "type": "bino", "command": "build", "artefact": "monthly_report", "group": "build" }
  ]
}
```

Errors and warnings that name a file and line go to the **Problems** panel; each
build replaces the previous build's entries. When the build reports PDFs, the
message offers **Open PDF** (a picker when there are several). Locally the PDF
opens in the system viewer, in a remote window it opens in VS Code.

## 8. Dependency Graph Navigation

The extension queries the manifest dependency graph (via the `bino daemon`,
falling back to `bino lsp-helper graph-deps`) to show dependencies and
dependents as a QuickPick list. For a plain-text tree/flat view instead, run
**Bino: Show Graph (Tree)** / **Bino: Show Graph (Flat)**, which runs `bino
graph` in the integrated terminal.

### 8.1 Opening the Graph

In the **Bino Explorer**:

1. Right-click any document (DataSet, DataSource, LayoutPage, ReportArtefact, etc.).
2. Choose one of:
   - **Show Graph (Dependencies & Dependents)**
   - **Show Dependencies**
   - **Show Dependents (What Uses This?)**

The extension runs a graph query for the selected node and opens a **QuickPick** listing related nodes.

### 8.2 Reading the QuickPick

Each entry shows:

- Label: `kind: name` with an icon.
- Description: relative file path.
- Detail: relationship to the root node:
  - `↓ dependency` - this node is a dependency (what the root uses).
  - `↑ dependent` - this node depends on the root (what uses the root).
  - `↕ both` - this node is both dependent and dependency.

Selecting an item:

- Opens the corresponding file.
- Attempts to jump to the correct document position based on the workspace index.

## 9. Designer

The **Bino Designer** edits a Table/Chart/Text/Tree/Grid manifest through a
schema-driven property form instead of raw YAML. It is a custom editor for YAML
files, so the text editor stays the default. Open it with:

- **Reopen Editor With... > Bino Designer** on a YAML file,
- **Bino: Open Designer**, the **Designer** CodeLens above a component, or
  **Open Designer** in the Documents view context menu,
- **Open in Designer** in the YAML editor's context menu (the manifest under the cursor).

- Fields are generated from the merged JSON schema for the manifest's `kind`.
- IBCS-specific fields (scenario, variance, stack, aggregate, edges) get
  purpose-built pickers instead of free-text input.
- A dataset/column picker is wired to live DuckDB column introspection.
- Edits are applied as scoped YAML patches (via the same authoring path as
  quick-fixes and Add Element), so the rest of the file (comments,
  formatting, unrelated fields) is left untouched.

### 9.1 ComponentStyle editor

**Bino ComponentStyle Editor** edits the `spec.content` of a
[ComponentStyle](/reference/component-style/). Open it with **Bino: Open
ComponentStyle Editor** (a button in the editor title bar of a YAML file that
holds a ComponentStyle), **Reopen Editor With...**, or the Documents view
context menu.

- One tab per section (`global`, `bn-table`, `bn-chart-time`, ...). It offers
  only the keys the template engine knows.
- An empty field shows the value it inherits, with its source: the style
  `_default`, or the engine default. A named style inherits from `_default`
  first.
- Clearing a field removes its key, so the YAML holds only your overrides.
- The SVG style groups (`barStyles`, `axisStyles`, `varianceStyles`) are a
  table per slot with a swatch of the resulting look. Colour lists and the
  named annotation colours have add, remove and reorder buttons.
- **Used by** lists the manifests whose `selectedStyle` names the style. Click
  one to open it in the embedded preview. The preview follows each edit, also
  before you save.
- When `spec.content` is a JSON string, the editor offers **Convert to YAML
  object** and changes nothing until then.

### 9.2 RuleSet editor

**Bino RuleSet Editor** edits a [RuleSet](/reference/ruleset/) as a table.
Open it like the ComponentStyle editor (**Bino: Open RuleSet Editor**).

- One row per scenario prefix (`ac`, `fc`, `pl`, `pp`, and other prefixes of
  the file), then the fallback row. Grey values are the engine defaults; only
  changed cells are written.
- `colorIndex` is shown as the four looks (solid, light, hatched, outlined),
  drawn in the colours of a ComponentStyle you pick at the top.
- Drag a row to change the column order. The editor writes `sortIndex` in
  steps of 100, and the variance order that follows from it is shown next to
  it.
- **Used by** works as in the ComponentStyle editor, through `ruleset`.

All edits go through the same path as the Designer, so undo, comments and
schema validation work as in the text editor.

### 9.3 Annotations view and form

The **Annotations** view in the Bino sidebar lists every
[Annotation](/reference/annotation/) by artefact, page and target component.
An annotation whose target is on no page is listed under *(target on no page)*.
Lint findings of an annotation (for example `annotation-target-missing` or
`annotation-point-missing`) show next to it.

- Click an annotation to show its YAML. **Edit Annotation** (the pencil, or the
  context menu) opens the form; **Delete Annotation** removes its document.
- **New Annotation** (the `+` in the view title) opens an empty form.
- The form shows only the fields of the chosen `mark`: `to` for arrow,
  difference, bracket and frame; `percent`, `digits`, `sentiment` and
  `highlight` for a difference; and so on. `color` offers the names of the
  `bn-annotation` colours.
- The target picker lists the components of the project. For a component with
  data points it offers the point fields of its kind, with the raw values of
  its dataset to pick from: type to filter them. A field left empty matches
  any value.
- A new annotation is written into the file of its target component.

**Annotate mode.** Both preview panels have an **Annotate** button once the
preview runs a bino that supports it. With the mode on, a plain click on a bar,
a table cell, a dot or any other data point opens the annotation form with the
component and the point filled in. For an arrow, a difference or a bracket the
next click fills `to`. **Pick in preview** in the form does the same for one
end. Cmd/Ctrl+click still shows the source, in the mode too. A live report
(`bino serve`) draws no annotations, so it has no button.

## 10. DataSource Wizard

Run **Bino: New DataSource from File…** (also available by right-clicking a
`.csv`/`.tsv`/`.xlsx`/`.xls`/`.parquet` file in the Explorer) or **Bino: New
DataSource from Database…** to scaffold a new DataSource + DataSet pair.

The wizard:

1. Introspects the source (sampling up to `bino.wizard.sampleRowLimit` rows).
2. Shows detected columns and inferred types.
3. Lets you pick which columns to include and preview the generated query.
4. Scaffolds the DataSource and DataSet manifests into the workspace.

## 11. Tree Editor & Rows Preview

- The **Bino Tree Editor** is a spreadsheet-like grid/property editor for
  hierarchical `Tree` documents, instead of editing nested YAML by hand. Like the
  Designer it is a custom editor: **Reopen Editor With... > Bino Tree Editor**,
  or **Bino: Open Tree Editor** (a button in the editor title bar of YAML files).
- **Bino: Preview Rows (100 rows)** - also available as a CodeLens directly
  above `DataSource`/`DataSet` manifests - opens a webview showing a live
  100-row data sample for that source.

## 12. SQL and PRQL

`query:` blocks are highlighted as SQL and `prql:` blocks as
[PRQL](https://prql-lang.org/). Inside them the language server:

- completes the bound sources' column names and, in SQL, DuckDB keywords and functions,
- completes DataSet and DataSource names after `FROM` / `JOIN`,
- goes to the definition of, and shows the columns and first rows of, a name after `FROM` / `JOIN`.

**Query diagnostics** are off by default. With `bino.lsp.queryDiagnostics` on,
saving a file runs each inline SQL DataSet query with `LIMIT 0` and shows DuckDB
parse and bind errors on the query lines. It reads no rows, but it may still open
remote sources.

:::caution[PRQL is currently not available]
bino runs on DuckDB 2.0, and the prql extension is not published for it yet. A PRQL DataSet fails to run, and the SQL preview below cannot compile PRQL. See [Using PRQL](/reference/dataset/#using-prql).
:::

For a `prql:` block:

- **Bino: Open PRQL Editor** opens the block in a dedicated editor.
- **Bino: Open PRQL SQL Preview** shows the SQL DuckDB will actually run.

The SQL preview needs the [PRQL VS Code
extension](https://marketplace.visualstudio.com/items?itemName=PRQL-lang.prql-vscode),
and the extension offers to install it.

## 13. Add Element

**Bino: Add Element** (the **+** in the Documents view toolbar) is the single entry
point for creating a manifest. It lists every kind bino knows, plugin kinds included,
grouped by category (data, layout, embeddable, artefact, config). DataSource and
DataSet open the DataSource Wizard. Every other kind asks for a name and the
fields it needs, then writes the file and opens it. It replaces the earlier
**Bino: Add &lt;Kind&gt;** commands.

## 14. Configuration Reference

All settings live under the **Bino Reports** section in VS Code Settings.

| Setting                      | Type    | Default | Description                                                                   |
| ---------------------------- | ------- | ------- | ----------------------------------------------------------------------------- |
| `bino.binPath`               | string  | `""`    | Path to the `bino` CLI. If not set, uses `bino` from `PATH`, then a downloaded bino. |
| `bino.columnCacheTTL`        | number  | 60000   | Column cache TTL (ms) for column lookups in the extension.                    |
| `bino.previewPort`           | number  | 45678   | Port number for the `bino preview` server.                                    |
| `bino.daemon.enabled`        | boolean | true    | Enable the persistent background daemon for faster indexing/validation/data.  |
| `bino.lsp.queryDiagnostics`  | boolean | false   | On save, check DataSet queries with DuckDB and show errors on the query line. |
| `bino.wizard.sampleRowLimit` | number  | 100     | Max sample rows the DataSource wizard fetches when introspecting a source.    |

Changes to `bino.binPath` and `bino.previewPort` apply at once: the language server and a running preview restart. A change to `bino.daemon.enabled` needs a window reload. `bino.lsp.queryDiagnostics` applies at once.

Example configuration:

```jsonc
{
  "bino.columnCacheTTL": 120000,
  "bino.previewPort": 3100,
  "bino.daemon.enabled": true,
  "bino.lsp.queryDiagnostics": true,
}
```

## 15. Troubleshooting

### 15.1 Bino CLI Not Found

- Symptom: Setup check fails, commands log errors like `bino: command not found`.
- Fix:
  - Install bino and put it on your `PATH`, set `bino.binPath`, or run **Bino: Download bino**.

### 15.2 No Completions or Hovers

- Confirm the file contains `apiVersion: bino.bi/v1alpha1` and a recognized `kind:`.
- Confirm the workspace is trusted.
- Check the **Bino Reports** output channel for `bino lsp` startup errors.
- Run **Bino: Restart Daemon**, or reload the window, to restart the language server.

### 15.3 Validation Errors

- Open the **Problems** panel to see details.
- Use **Go to First Problem** from the Bino Explorer context menu for a document.

### 15.4 Daemon Rejects the Extension

- Symptom: "The running bino daemon rejected this extension".
- Fix: click **Restart Daemon** (see [MCP server](#mcp-server)).

### 15.5 Debug Logs

- Open the **Bino Reports** output channel:
  - `View → Output`, then select **Bino Reports** from the dropdown, or **Open Log** in the status bar menu.
- All CLI invocations and errors from the indexer are logged here.
